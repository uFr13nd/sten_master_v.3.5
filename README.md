# 🧱 СТЕН·МАСТЕР v3.5 WEB

Веб-версия Google Sheets-калькулятора **СТЕН_МАСТЕР v3.5** для публикации на GitHub Pages.

Главный принцип этой версии: **интерфейс можно улучшать, расчётную модель нельзя "приблизительно переписывать"**. Расчётный движок повторяет формулы главного листа v3.5, а справочники, составы конструкций, отделка и логистика синхронизируются из Google Sheets через Apps Script.

## Что входит в репозиторий

```text
.
├── index.html        # интерфейс
├── styles.css        # дизайн строго в утверждённой палитре
├── engine.js         # чистый расчётный движок v3.5
├── data.js           # проверенный fallback-снимок Google Sheets
├── app.js            # интерфейс, состояние, синхронизация, админ-панель
├── Code.gs           # Apps Script v3.5 + Web API + аудит
├── MODEL_PARITY.md   # карта формул Sheets → JavaScript
└── tests/
    └── golden.test.js
```

Сторонние JS-фреймворки и npm-пакеты не требуются.

## 1. Что перенесено из Google Sheets

- город объекта;

- периметры трёх категорий стен;
- высота и этажность;

- проектный материал и проектная отделка;

- перегородки;
- доставка;
- отделка;
- стоимость работ и материалов отдельно;
- итоговые прямые затраты;
- изменение площади относительно проектного решения;
- изменение продаваемой площади и её стоимости;
- правило `совпадает с проектным материалом → 0` в изменяемых решениях.

- `Работы`, коды `W-xxx`;
- `Материалы`, коды `M-xxx`;

### Системная логика

`Code.gs` объединяет систему v3.5 и Web API:

- аудит изменения цены;
- аудит групп;
- журнал `кто / что / было / стало / когда`;
- синхронизация баз;
- контроль целостности;
- отчёт по стратегическим материалам;
- присвоение новых кодов;
- backup;
- изменение расценок из веб-интерфейса;
- правило максимальной цены для дублей одинакового наименования и единицы измерения.

## 2. Проверка точности

`engine.js` отделён от интерфейса и тестируется без браузера.

В fallback-снимок включены контрольные результаты живого Google Sheets v3.5. Тест сравнивает:

- толщины;
- площади/объёмы;
- массу;
- количество условных единиц;
- цену конструкции;
- работу и материалы;
- машины и доставку;
- отделку;
- итог по каждой категории;
- все показатели итоговой сводки.

На момент сборки:

```text
Golden tests: 186/186
```

Запуск:

```bash
node tests/golden.test.js
```

При синхронизации Web API возвращает также актуальный контрольный baseline главного листа. Поэтому интерфейс может проверять совпадение JavaScript-движка уже с **текущими**, а не только со встроенными ценами.

## 4. Установка Apps Script

### Важно

`Code.gs` должен **заменить** старый код Apps Script целиком. Не добавляйте его вторым комплектом рядом со старыми `doGet`, `onOpen` и аудитом.

1. Откройте Google Sheet.
2. `Расширения → Apps Script`.
3. Удалите старый код проекта.
4. Вставьте содержимое `Code.gs`.
5. Сохраните.
6. Один раз выполните:

```text
setupSystemV35
```

7. Подтвердите разрешения.
8. Затем один раз выполните:

```text
setupWebApi
```

`setupWebApi()` создаст ключ администратора и запишет его на листе:

```text
Система_v3.5 → Admin key
```

**Не публикуйте этот ключ в GitHub.** Веб-приложение просит его только при входе в режим администратора и хранит в `sessionStorage` текущей вкладки.

## 5. Публикация Apps Script как Web App

В Apps Script:

```text
Deploy → Manage deployments → New deployment
Type: Web app
Execute as: Me
Who has access: Anyone
```

После изменения кода существующий deployment можно обновить, сохранив тот же URL.

URL API указан в начале `app.js`:

```js
const API_URL = 'https://script.google.com/macros/s/.../exec';
```

Если создаётся новый deployment с другим URL, замените только эту строку.

### Почему публичный GET допустим

Публичный `bootstrap` отдаёт только данные, необходимые самому калькулятору: цены, группы, конструкции, отделку, доставку и параметры модели.

Изменение данных, аудит, backup и системные операции работают только через POST с `Admin key`.

## 7. Режимы работы веб-калькулятора

### Онлайн

При загрузке приложение получает актуальную модель из Google Sheets.

В шапке отображается:

```text
Google Sheets · HH:MM
```

### Fallback

Если Apps Script недоступен, калькулятор не превращается в белый экран. Используется встроенный `data.js` — снимок v3.5, прошедший 186 контрольных тестов.

В fallback-режиме расчёт работает, но изменение централизованных расценок через веб недоступно.

## 8. Изменение расценок через веб

Вкладка **«Расценки»** показывает те же `Работы` и `Материалы`.

Для редактирования:

1. Нажать `Режим администратора`.
2. Ввести `Admin key`.
3. Указать email/ФИО редактора, если Google Session не возвращает email.
4. Изменить цену или группу.
5. Нажать `Сохранить`.

Backend:

1. блокирует документ на время записи;
2. записывает старое и новое значение;
3. обновляет `Предыдущая цена / Дата / Изменил` для цены;
4. пишет `Журнал_цен`;
5. применяет правило максимальной цены к дублям;
6. синхронизирует базы;
7. обновляет snapshot аудита;
8. возвращает заново рассчитанную модель.

То есть браузер не пытается самостоятельно "переоценить" базу после изменения прайса. Google Sheets пересчитывает свои формулы и возвращает веб-приложению результат. Так исключается расхождение между двумя сметными движками.

## 9. Локальный запуск

Для простого просмотра можно открыть `index.html` напрямую: fallback-модель уже встроена через `data.js`.

Для теста синхронизации с Apps Script лучше использовать любой локальный HTTP-сервер, например:

```bash
python -m http.server 8080
```

и открыть:

```text
http://localhost:8080/
```

## 10. Важное архитектурное решение

Веб-версия не хранит второй независимый набор сметных цен.

```text
Google Sheets
  ├── Работы
  ├── Материалы
  ├── База_Наружные
  ├── База_Межквартирные
  ├── База_Перегородки
  ├── База_Отделка
  └── База_Доставка
          ↓
       Code.gs API
          ↓
     GitHub Pages UI
```

Google Sheets остаётся мастер-источником справочников и состава конструкций. JavaScript повторяет геометрию, логистику, отделку и итоговую проектную логику главного листа.

Это намеренно. Два полностью независимых справочника цен неизбежно расходятся. Люди отлично умеют создавать такую проблему даже без дополнительной помощи программного обеспечения.
