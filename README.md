# СТЕН·МАСТЕР v3.8 WEB

Веб-версия калькулятора стен, синхронизированная с рабочей Google-таблицей `СТЕН_МАСТЕР_v.3.7`.

## Что изменено в v3.8

### Расчёт

- доставка показывается **справочно** и не входит в итог сценария;
- цена материалов трактуется как цена **с НДС и доставкой**;
- стоимость выбранного решения считается всегда;
- изменение площади равно нулю только при полном совпадении **материала + отделки** с проектом;
- полистиролбетонные конструкции и решения со статусом `Не проходит` не выдаются пользователю;
- доборные элементы с нулевым вкладом не участвуют в стоимости;
- fallback-снимок собран из Google Sheets v3.7;
- regression check: `186 / 186` контрольных значений.

### Интерфейс

- `⚙ Администрирование` вынесено в верхнюю панель и отдельный заметный раздел;
- кнопка `PDF отчёт` формирует PDF по текущему расчёту через Apps Script;
- добавлен раздел `📈 История цен` с выбором материалов и группировкой;
- добавлен раздел `📄 Сертификаты`;
- добавлена встроенная инструкция и постоянная ссылка на неё в подвале.

### Администрирование

После подключения Admin key администратор может:

- менять цены, технические и закупочные группы;
- добавлять новый материал напрямую в `Материалы!A:S`;
- автоматически получать следующий код `M-xxx`;
- загружать сертификаты и протоколы PDF/JPG/PNG;
- удалять сертификаты;
- синхронизировать базы;
- запускать контроль целостности;
- формировать отчёт по стратегическим материалам;
- присваивать новые коды;
- создавать backup Google-таблицы.

## Сертификаты

При первом запуске `setupWebV38()` Apps Script создаёт:

- лист `Сертификаты`;
- папку Google Drive `СТЕН_МАСТЕР_Сертификаты` рядом с таблицей.

Файл сертификата хранится **один раз** в Google Drive. В публичный bootstrap попадает только безопасная метаинформация без Drive file ID. Когда пользователь открывает документ, Web API проверяет ID сертификата по реестру и отдаёт файл. Поэтому сертификаты доступны всем пользователям веб-калькулятора, но сама папка Drive не обязана быть публичной.

Максимальный размер одного сертификата: **8 МБ**.

## История цен

Графики строятся по `Журнал_цен`.

Публичный endpoint не возвращает имя пользователя, который менял цену. Он отдаёт только:

- дату;
- код материала;
- предыдущую цену;
- новую цену.

Варианты группировки в интерфейсе:

- техническая группа;
- группа закупки;
- единица измерения;
- без группировки.

Сами линии остаются линиями конкретных материалов. Цены за `м³`, `кг` и `шт` не усредняются между собой, потому что даже браузер не должен совершать такие преступления против размерностей.

## PDF отчёт

Кнопка `PDF отчёт` отправляет текущий расчёт в Apps Script. Backend:

1. создаёт временный Google Doc;
2. формирует отчёт с исходными данными, проектом и тремя сценариями;
3. экспортирует его в PDF;
4. удаляет временный Google Doc;
5. возвращает PDF браузеру.

Если backend ещё не обновлён до v3.8, интерфейс использует печатную версию браузера как fallback (`Сохранить как PDF`).

## Новые материалы

Форма администрирования создаёт строку в формате листа `Материалы`:

`A:S = код, наименование, ед., цена, предыдущая цена, дата, изменил, техническая группа, использование, комментарий, группа закупки, габариты, плотность, прочность, источник, статус проверки, комментарий по единице, звукоизоляция, статус в калькуляторе`.

Код назначается автоматически. Система не позволяет добавить точный дубль `наименование + единица`.

> Добавление материала в справочник **не создаёт автоматически новую конструкцию стены**. Для появления нового материала в выборе калькулятора нужно отдельно добавить/связать конструкцию в соответствующей `База_*`, потому что состав работ и нормы расхода нельзя разумно угадать из одного названия материала.

## Установка backend v3.8

В Google Sheet:

1. `Расширения → Apps Script`.
2. Заменить существующий код содержимым `Code.gs` из этого релиза.
3. Сохранить.
4. Один раз вручную запустить:

```text
setupWebV38
```

5. Подтвердить разрешения Google Drive / Docs, если Google их запросит.
6. `Deploy → Manage deployments`.
7. Открыть текущий Web App deployment и создать **новую версию**, сохранив тот же URL.
8. Проверить `.../exec?action=health` — ответ должен содержать `3.8-web`.

Существующий Admin key сохраняется, если он уже был создан раньше.

## Публикация GitHub Pages

В корне репозитория должны находиться:


После commit/push GitHub Pages обновит сайт из настроенной ветки.

## Безопасность

- Admin key **не хранится** в репозитории и frontend-коде.
- В браузере он хранится только в `sessionStorage` текущей вкладки.
- Изменение таблицы, добавление материалов, загрузка/удаление сертификатов и системные команды требуют Admin key.
- Просмотр цен, расчёт, история цен без авторства, PDF отчёт и чтение сертификатов доступны обычным пользователям.
- Сертификаты выдаются через реестр Apps Script, а не прямым публичным Drive file ID.
